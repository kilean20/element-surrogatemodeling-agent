# General scientific feedback for evolving ESA

Preserve useful lessons locally while working, then offer a curated batch at a
meaningful milestone or the user's request. Prioritize accelerator physics and
reusable constraints: field readiness/Maxwell interpretation, numerical versus
mechanical aperture, reference/design orbit and handedness, charge/sign/units,
slopes versus canonical variables, static maps versus true timing, reconstruction
and convergence, model physics/symmetry, fair benchmarking and sample/optimizer
adequacy. Include user corrections and unexpected tool/workflow behavior. Other
important general modeling/software lessons are welcome; do not invent user quotes.

## Share the lesson and its applicability

Explain the problem, observed evidence, reasoning, proposed improvement and
limitations. Distinguish an observation, reproduced result and untested idea.
Use public references or a manufactured minimal reproduction when possible.
Keep only context needed to assess the lesson: ESA/relevant dependency versions,
element type/map dimension and coarse constraints such as one available excitation,
unknown geometry, CPU-only compute or unavailable network. These are not claims
about all cases. Preserve original detailed evidence privately in the project.

| Keep in a proposed shared report | Generalize or omit |
|---|---|
| Canonical and slope charts must be distinguished in symplectic tests | Private beam settings, lattice/magnet names and facility geometry |
| A normalized-loss comparison changed the architecture conclusion | Private training rows, weights, exact machine operating points or field identities |
| One excitation field cannot establish arbitrary-current shape changes | Local calibration tables, operational currents and proprietary source documents |
| Unknown geometry led to a declared numerical research region | CAD/pipe/pole dimensions or a claim that support proves physical clearance |
| Memory-limited or offline execution required a reusable workflow repair | Hostnames, addresses, usernames, paths, account/resource IDs and environment dumps |

Never attach raw fields, particle/model payloads, full conversations, credentials,
personal contacts or confidential/internal documents. Do not automatically crawl
the project or transcript to assemble an outgoing report. Do not send sensitive
material even if it appears useful. Generalize first, retaining only sufficient
non-sensitive evidence; explain when that limits reproducibility.

## Compare with ESA's installed guidance

Use [installed-guidance comparison](installed_guidance_comparison.md) to identify
the actual baseline, existing instruction, observed difference, classification,
importance and proposed action. Distinguish new knowledge from a correction,
clarification, tool defect, guidance-following failure or private case fact.
Include an accurate generalized comparison in the reviewed packet; keep detailed
local context private. Uncertain novelty must be labeled, not asserted.
