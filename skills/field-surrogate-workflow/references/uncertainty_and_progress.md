# Uncertainty: analyze, decide and keep useful work moving

Read when missing, conflicting or unavailable facts affect the map's meaning,
supported domain or claims. Consequential does not mean blocking. Use existing
facts, decisions and delegation first. Do not demand a completed questionnaire,
new field calculation or known physical aperture before every numerical study.

## Ask usefully, then own the scientific decision

Inspect available metadata and numerical evidence first. Ask a short grouped
question if an accelerator physicist may resolve an important ambiguity. Propose
a reasoned default/scope and explain its consequence. Do not ask the user to pick
steps, stencils, widths or other choices ESA should investigate. Ask only what
matters to this task; species/mass is unnecessary for a signed-rigidity-only4D map.

Distinguish not supplied, pending, answered unavailable, supplied/derived and
delegated. A missing file is not proof the user does not know. Conversely, after
“I don't know”, “no better field exists”, a declined question or explicit
delegation, do not repeat the question or wait forever. Continue analysis, compare
feasible alternatives and **tell the user the decision, evidence and limits**.
Pending questions do not stop work independent of the answer. A new scope choice
is different from re-asking an unavailable fact; reuse existing authority rather
than inventing approvals. New source facts can justify a genuinely new question.

For example: “No mechanical aperture is available. The source/support and tracking
checks support this declared numerical region. I will use it for the requested
research map; it does not certify physical transmission.” Derive actual region
values from this field's evidence; no example radius is a package default.

## Practical alternatives

| Uncertainty | Useful analysis/decision when the user cannot resolve it |
|---|---|
| Unknown physical aperture or material mask | Examine raw-field behavior, coverage and actual reconstruction nodes; compare numerical path regions and losses. Use a qualified numerical research domain under existing authority. Do not call it a measured bore or a physical loss classifier. |
| No improved source field or CST convergence record | Retain raw diagnostics/defects. Analyze support, sensitivity and step/reconstruction effects within budget; restrict support or qualify approximation where defensible. Model the supplied numerical field with explicit source uncertainty rather than quietly idealizing it. |
| Current-to-field calibration unavailable | Keep calibration outside the map. Use defined physics inputs such as B2 or B2/Brho; missing current calibration need not block them. Record known source current as provenance. Several excitation fields can support shape dependence; a calibration inside the model requires explicit scope and evidence. |
| No external design orbit/stations | Propose and record supported native planes and a fixed traced/reference convention. A defined numerical frame is useful; do not claim it equals an unavailable design orbit. Element placement remains composite work. |
| Uncertain symmetry | Measure field and map effects; compare general and structured models rather than enforcing an unsupported exact symmetry or omitting its study. |
| User unsure about goals or population | Follow existing pilot/ETA, adequacy and multi-speed tradeoff procedures. State provisional assumptions; do not silently lower explicit goals or replace full data with a small pilot. |
| Missing actual mass/momentum for arrival time | Continue field/trajectory/transverse work. Offer path-length output or a declared partial artifact if within authority; true time remains unavailable. Do not silently substitute coordinates or infer speed from effective rigidity encoding a field error. |
| Unsupported requested physics or unusable numerical inputs | Explain the precise limitation and analyze remaining valid options. Return useful diagnostics/partial results; do not pretend an undefined requested output or failed computation succeeded. |

Changing scope is not permission to change the user's intent. If an alternative
requires new authority, propose it and continue independent authorized work.
An immutable explicit refusal/budget/consent requirement cannot be reinterpreted.
There is no universal guarantee that an arbitrary broken field admits a useful
surrogate; honest partial results can be the scientifically correct outcome.

## Read actionable tool warnings

High-level readiness/review results include structured `warnings` with an issue
code, evidence reference and recommended action. Inspect them alongside actual
case decisions: unresolved does not mean the user can or must supply a fact.
Complete scientific interpretation, compare supported options and communicate
the chosen scope. Warnings do not force a question or change eligibility;
invalid inputs, source mismatches and actual execution failures remain errors.
No warning is needed on each particle or repeated tracking step.

## Record the reasoning, not another approval hurdle

For a material unresolved decision, use `write_scientific_uncertainty_review`
with the installed `uncertainty-review` example. Store the request/report in
`records/uncertainties/` and link it from the case report/resume note. Record
available evidence, considered alternatives, the chosen plan and authority,
work that can continue, unavailable outputs and retained limitations. Read these
records and actual user replies when resuming; do not infer an answer from silence.
An empty review is permitted. No fixed topic/question count or new universal
deadline applies. Simple cases do not need a ceremonial review file.

This helper records client judgment and gives question-pacing guidance. It does
not authenticate a user, validate the physics automatically, create approvals or
become a prerequisite for generation/fitting/export. Existing request schemas
and decision/qualification mechanisms stay unchanged. Do not submit its report
as a scientific qualification or user-approval file.

## Keep existing numerical safeguards and truthful claims

The readiness review already supports `accepted_numerical_limitation` and
reviewed unknown geometry for scoped numerical research. Preserve every finding,
its interpretation and source identity. Missing physical provenance differs from
a diagnostic execution/resource error. A source mismatch, unsupported stencil,
non-finite state, failed numerical qualification, resource limit or missing
required authorization cannot be waived by this advisory note. Diagnose, use an
inspected/requalified alternative or defer only the unsupported output.

Cards/report/resume should say what was completed in its declared scope and what
cannot be established. Unknown physical geometry or governance is not the same
as unfinished numerical training. Source-calculation, numerical-teacher and
learning errors remain separate. Feedback, classification and sharing readiness
never become new dependencies of local scientific work.

Software tests cannot prove the LLM follows this procedure. Behavioral claims
need actual fresh installed conversation records, including “unknown” answers and
observed continuation. Do not inherit broader qualification from earlier versions.
