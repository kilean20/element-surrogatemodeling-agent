# Independent local deployment and evidence boundaries

Open the software source folder and follow ../SETUP.md to install into a private
Python environment and configure a new or existing project. The helper reuses
the released doctor, initializer, numerical smoke and MCP interfaces.
Follow the complete platform commands in the installation guide. Installation needs
neither the developer's research repository nor the developer's user skills.
The [Codex/Claude Code installation guide](installation.md) and [usage manual](usage_manual.md)
give explicit Windows/Linux commands, request examples and scoped qualification.

The package carries five workflow skills, general physics
knowledge entries, the reused benchmark-builder core, and the pinned Genesis
datacard/evaluation asset closure. No case memory, field arrays, training rows,
model parameters, environment or credentials is part of the distribution.
A new case starts with empty visible records/; an existing case retains its state. No default original author, sponsor, license,
sensitivity, institutional publisher or scientific approval is inherited.

The setup installs skills to `.agents/skills` for Codex and `.claude/skills` for
Claude Code. It adds the current environment's Python MCP command and explicit
case directory to project `.codex/config.toml` or `.mcp.json`.
Unrelated client settings remain; managed-file hashes protect user edits.
Client project trust/approval is not bypassed. Configuring files does not prove
that an AI client used the tools correctly in an autonomous campaign.

## Supported scientific and runtime scope

Static magnetic grids, signed rigidity, fixed native reference planes and
4D/5D/6D slope/momentum-deviation/arrival contracts are implemented. One static
shape with scalar amplitude can reduce to amplitude/effective rigidity. A
non-scaling solved-field family, electric/time-varying fields, general material
geometry and a full 6D canonical/gauge map need additional explicit backends.
Reconstruction defaults to total-degree-two; integration is qualified per field
and range. Empirical qualification is not a uniform error certificate or an
inferred mechanical aperture.

The general and residual neural models support 4D/5D/6D. The paraxial quad base
supports 4D/5D aligned native planes; the drift base also supports 6D path/time.
The potential-shear backend is restricted to eligible 4D canonical coordinates.
Its conservative sufficient test requires zero projection on both native normals
throughout the supplied grid. Transverse magnetic two-form diagnostics support
fixed-momentum slices of all dimensions; they do not certify a full 6D map.

Generation uses bounded batches and exact read-only memory-mapped field storage.
The full-resolution readiness path processes bounded node windows and retains
local/worst-case evidence; its block limits are not a process-wide RAM cap.
Some analysis and benchmark cohort/preprocessing operations still materialize
working arrays. Choose a declared resource allowance, inspect dimensions and
measure peak memory and throughput for the intended workload. No GPU/HPC is
required, and no production-scale GPU throughput is claimed.

## Native inference and reference frames

`element_surrogate.export.ElementSurrogate.predict` is fast native inference
when numerical support has been independently established. `predict_checked`
verifies source identity and tracks arbitrary proposals; its cost includes field
identity checks and full tracking. Inputs use the native coordinate contract,
effective rigidity and field amplitude. Lattice placement is outside this API.

The current moving reference frame is upright. Vertical tangents requiring a
different roll policy are unsupported. Explicit coordinate/reference contracts
remain authoritative; higher-dimensional support does not establish a general
full-6D canonical/gauge map.

prebuilt wheel, uv installation or generated workspace manifest is required.
See [START_HERE](../START_HERE.md), [AI setup](../SETUP.md),
